04 / GATES & CHECKERS

代码写完，接下来发生什么

顺序来自实际调用。展开 diff 门禁查看 Python 子检查。

序号为调用顺序，不表示每次都会执行。完整收尾先识别范围，失败立即停止；后续检查尽量跑完再汇总失败。轻量 / 单点的收尾组合见上方档位视图。

05 / REVIEW & DELIVERY

脚本之外，仍要判断

自动扫描能给出证据，但不能证明业务口径、并发或查询计划正确。

人工 / Agent 核查

查询与业务语义

核对 JOIN 来源、数据归属、索引覆盖、循环规模、幂等与失败可见性。索引 DDL 提示不等于索引覆盖已验证。

条件审查

按风险选择审阅

先清 lint / compile 失败。快速收尾自审；涉及权限、数据或并发行为变化时，按实际风险补充审阅。

P0 / P1 必须清零

审计 → 最终交付

完整档先给《变更审计》，修复后再审。P0 / P1 清零才给《最终交付清单》；P2 可登记遗留，接口文档 和索引命中须明示。

沉淀与跨会话

有用户纠正或规则未能防住的险错才记待沉淀，不自定级。完整且预计多轮时维护 .agent handoff；完成后更新状态。commit / push 需要用户授权。

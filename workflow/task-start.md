# 开任务（Agent 内部）

> **用户只说要做什么。** 本流程由 Agent 自动遵循，不要让用户输入额外命令，不要让用户确认档位。

## 0. 先判轻重（先于完整阅读）

默答下面 5 问。答得出就开干，答不出才问业务事实。档位定义只认 `.cursor/rules/agent-workflow.mdc` 的三档表，这里不另列一张。

| # | 问 | 用来干什么 |
|---|----|---|
| 1 | 交付物是什么？（配置 / 数据 / 接口 / 修 bug） | 认清目标，禁止加戏 |
| 2 | 最少改几个文件能交差？ | 文件数是最硬的信号 |
| 3 | 会改受保护结构吗？（表结构 / 表关联） | 若会，按内核立刻读 `java-wiki.mdc`；不因此把已有 SQL 或已有 Job 升档 |
| 4 | 会动受保护数据吗？ | 若 `AGENTS.md` 启用了对应 pack，立刻按该 pack 过滤；不因此升档。本仓库没有受保护表名单 |
| 5 | 会新增被代码引用的配置吗？ | 按项目配置读取约定核对引用与交付 |

未启用领域规则时仍识别结构和数据风险，但不要臆造该领域的过滤、常量或交付要求。写非主键 SQL 走 `java-index.mdc`（核对索引覆盖，不升档）；不是第 6 问，不参与判档。

拿不准选更轻的一档。轻量随后只改落点。单点做 §2。完整做 §1 再做 §3。

## 1. Handoff（仅完整档）

1. 列出 `wiki/.agent/*.md`
2. 有 `status: in_progress|blocked` → Read 并续写
3. 新任务且预计 >1 轮 → 创建 `wiki/.agent/<task-slug>.md`

## 2. 单点

Read 目标模块 1～2 个同类实现（或 1 篇直接相关 wiki），然后改那些文件。禁止为「流程完整」打开 `task-routing` 全文或新建 wiki。

## 3. 最小阅读集（仅完整档）

1. `AGENTS.md`
2. `workflow/guides/agent-essentials.md`
3. `workflow/guides/task-routing.md` → 按场景追加 1～3 篇

## 4. 加载

Cursor 按 MDC 的 `alwaysApply` / `globs` 注入，不必按下面清单再逐份打开。Codex 没有 glob，开任务读取：

1. `AGENTS.md`
2. `.cursor/rules/agent-workflow.mdc`
3. 本文件的判档部分
4. 计划修改路径与语义钩子命中的全部规则，以及已有 custom/local

适用规则取并集，钩子优先于路径。修改 Entity 时读取 Java 项目规范；确有结构变化再加载交付、Wiki 与索引规则。轻量只停止完整阅读，不停止规则路由。加载规则与执行检查分开判断：例外允许跳过具体检查，不等于无需阅读。

中途范围扩大，立即补读新命中的规则。脚本 TAGS 只提供识别线索，缺少标签不能免除按实际行为加载规则和核查的责任。

## 5. Agent 自检（不单独发给用户）

- 档位、分支、已 Read 文档、参考样板
- 收尾命令只认内核「收尾」表
- 完整任务结束时，按 `workflow/guides/change-audit-checklist.md` 输出《变更审计》；P0/P1 全清后继续输出《最终交付清单》

## 禁止

- 让用户执行脚本、触发额外命令或确认档位
- 完整档未 Read 路由就写跨模块代码
- 表关联无文档时臆造 JOIN
- 用「这是单点」跳过已启用领域规则、`java-index` 索引核对或 `lint-agent-diff.sh`

三档表「明确不做」里已有的限制（轻量不写专题 wiki、不跑 `finish-audit.sh`）不要在这里再抄一遍。

# Agent 项目补充规程

本规程供 Agent 执行，完整接入和针对项目适配均须携带。你负责发现缺口、查找已有资料、整理候选内容、落实已确认约定并验证；不要把空表交给使用者填写，也不要一次询问所有事项。

## 执行边界

基础接入提供通用工作流。项目适配解决已有入口、目录和规则的兼容；两者都不授权你根据 DO、Entity、Mapper、Job 等命名制定项目规范或新增专用 glob。已有明确生效的约定可以直接引用；源码只能证明观察到的实现，不能证明整个团队必须这样写。

普通任务开始时查看接入记录中的未完成项，只处理影响当前任务的缺口。不要求先补齐全库或全部规范；已确认的内容不重复询问。使用者负责业务判断和约定选择，你负责其余整理与落盘工作。

## 执行顺序

1. **收集证据**：读取已有 AGENTS/MDC、项目文档、构建文件、脱敏结构资料和必要的同类实现。记录文件及版本或日期，不收集凭据，不擅自连接数据库。
2. **分类判断**：区分“已生效约定”“可核实事实”“待确认建议”。目录、类名和局部写法只能作为事实或候选，不能自动变为全仓规范。
3. **推进当前缺口**：先完成能够自行取证的事项。确实缺少业务含义、选择或权威来源时，只询问当前任务所需的具体问题，并给出已经查到的依据及缺少它的影响。
4. **维护权威内容**：复用已生效约定，或在使用者确认后更新相应 MDC、配置、数据库字典或业务 Wiki。只有明确的规则范围才可以增加专用路径触发；不批量迁就所有源码命名。
5. **验证并记账**：运行变更相关检查，把“文档格式通过”“配置可执行”“业务内容核验”分别记录。更新目标 `.local/knowtrail/adoption.md` 的补充记录，随后报告完成项、待确认项和对下一步的影响。

## 逐项核查

| 项目 | Agent 收集和核实什么 | 最终维护位置 | 缺失时的行为 |
|---|---|---|---|
| Java 规范 | 已有分层、命名、注释、异常、日志、持久化规范及适用范围 | java-coding-standards.mdc 或其引用的项目规范 | 阅读同类实现；不将局部写法升级为强制标准 |
| 项目 MDC | 已生效业务约束、触发语义、必要的路径范围及冲突 | custom/、对应 MDC、AGENTS | 保留通用钩子；不从 DO/Entity 等名称自动生成专用 glob |
| 业务边界 | 权限、数据归属、敏感数据、禁止操作及受保护范围的权威依据 | 项目 MDC、业务 Wiki | 仅在相关任务缺关键事实时询问，不预设过滤字段 |
| 构建环境 | POM/Wrapper/既有脚本中的工具、JDK 要求与模块构建方式 | Java 项目规范、workflow/config.json | 不自动安装或切换 JDK；外部父 POM 未解析不等于版本已确认 |
| 测试与门禁 | 已有测试入口、运行前提、附加检查及失败语义 | 项目规范、config 的 checks | 不把编译当测试；区分未执行和通过 |
| 数据库资料 | 引擎/版本、逻辑库、可信脱敏 DDL 或结构来源 | wiki/database/README.md、index.md | 不把配置示例 app 当真实库，不从 Java 字段推断完整 DDL |
| 表字典 | 字段含义、类型、主键、唯一约束、已有索引及资料版本 | 数据字典及相关专题 | 先补本次涉及的表，不强求全库一次整理 |
| JOIN 关系 | 关联键、基数、可空性、范围与聚合语义 | 数据字典、业务 Wiki | 不凭同名字段猜 JOIN；关键关系不明时停止相关实现 |
| 查询与索引 | 规模、热表、查询预算、计划来源和变更窗口 | java-index.mdc、相关 Wiki；必要时 hot_tables | 不把静态核查称为计划验证，不预填热表名单 |
| 结构交付 | 已有迁移工具/目录、版本策略、发布保护、恢复方式 | java-version-delivery.mdc、项目迁移说明 | 示例 version-sql 保持关闭，不能为了完整接入而启用 |
| 业务知识 | 已有模块边界、术语、状态流转和接口/任务/MQ 说明 | wiki/index.md、模块 README、专题 | 源码导航仅是草稿，未经核实不批量生成业务知识 |
| 知识维护 | 权威来源和维护约定；是否需要复核提醒 | wiki/README.md、项目规范 | 遵循模板和索引；长期未更新不自动判错 |

## Agent 维护的补充记录

在目标 `.local/knowtrail/adoption.md` 建立下表；已有记录则续写，适配后使用实际记录路径。逐项写具体状态和下一步，不将本规程中的示例当成验收结果。

| 项目 | 状态 | 来源 / 候选内容 | 权威落点 | 下一步或实际验证 | 确认依据 / 日期 |
|---|---|---|---|---|---|
| 按上表逐项记录 | 待取证 / 待确认 / 已落实 / 不适用 | 实际证据；未知写明缺口 | 实际文件 | 由 Agent 执行的具体动作 | 已有生效文档或使用者决定；未知不填 |

“已落实”要求有有效依据、完成落盘和适用验证；不适用必须说明原因。待确认只用于确实需要使用者判断的内容，不能把 Agent 尚未查找资料伪装成等待使用者。

## 交付口径

- **基础接入**：通用入口、文件链、脚本、Wiki 模板及看板的实际验收结果。
- **项目补充**：已落实约定、仍缺资料或需要确认的事项，以及受影响场景。
- **业务验证**：实际任务的编译、测试、运行及领域核验；未做的明确列出。

基础接入可以在项目补充未完成时独立验收；这不等于全部业务场景已经可用。关键事实缺失只影响相关任务，不阻塞无关工作。不要把本轮用户排除的验证改写成永久豁免。
